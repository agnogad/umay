# ADR 0007 — MIR design and lowering strategy

- **Status**: accepted
- **Date**: Phase 3
- **Supersedes**: nothing

## Context

Phase 2 produced a typed HIR: a tree in which names are resolved, types are
attached, and sugar such as `for` loops and interpolation is represented
explicitly. Two things were missing before ownership checking could be written.

First, a representation in which control flow is a graph rather than a tree.
Definite initialisation, move analysis and drop placement are all questions
about *paths*, and a tree cannot answer them without re-deriving the graph each
time.

Second, a decision about where to remove sugar. Language sugar in a tree is
convenient for diagnostics, since every construct has a source span and a shape
the user recognises. But `&&` must not evaluate its right operand eagerly, `?`
must branch and return, and `match` must become a decision tree. All three need
control flow, which lives in MIR.

## Decision

### 1. MIR is a CFG of blocks with explicit terminators

A `Body` is a list of `BasicBlock`s. Each block holds statements and ends in
exactly one `Terminator` (`Goto`, `SwitchInt`, `Call`, `Drop`, `Return`,
`Unreachable`). Every jump names its target block; there is no fallthrough.

Fallthrough is the usual source of subtle bugs in CFG code, because a block can
end with or without a terminator and every consumer has to cope with both. By
requiring exactly one terminator per block, consumers never need a special case.
The lowering keeps a placeholder `Unreachable` terminator on blocks under
construction; attaching a real terminator replaces it.

### 2. Every sub-expression becomes a temporary

`a + b * c` lowers to: a temporary for `b * c`, then a temporary for the sum.
The alternative — an `Operand` tree inside a statement — would let a statement
express nested computation, and every later pass would have to walk it.

With operands restricted to *places* and *constants*, ownership reasoning is
local: a move is an operand marked `Move`, a drop is a terminator naming a
place. Nothing has to descend into a statement to find the moves it contains.

### 3. Sugar is removed in lowering, not in HIR

`for`, `?`, `&&`, `||`, string interpolation and `match` all become explicit
branches in MIR. The HIR keeps its source-shaped form so that diagnostics can
point at the construct the user wrote.

Interpolation lowers to a sequence of `intrinsic:str_concat` and
`intrinsic:str_append_display` calls, identified by interned strings. The
backend resolves those names; MIR needs no special instruction for formatting.

### 4. Drop elaboration is a separate pass over the CFG

Ownership says *that* a value is dropped; elaboration says *where*. The pass
computes, per block, the set of locals whose drop flag is still set, using the
`SetDropFlag` statements the lowering emits and the `Drop` terminators it
inserts. It then puts a `Drop` chain before every `Return` and `Unreachable`
that has live owned locals.

Two details are load-bearing:

- **Reachability.** A block that nothing jumps to must not contribute to the
  analysis. Without this, a dead block left behind by lowering made values look
  live on a path that cannot happen, and produced a drop on a nonexistent path.
- **Moves are flag writes.** A move lowers to `SetDropFlag(false)` before the
  operand, so the analysis needs no special case for moves: the flag is the
  single source of truth about whether a local still owns a value.

The pass is skipped entirely when a function has no owned locals, so most
functions gain no blocks at all.

### 5. A text format with a parser, used for testing

`mir_print` produces a stable, complete text form; `mir_parse` reads it back.
This is what makes the lowering testable at the level of *shape* rather than
only at the level of "it did not crash": a test can assert that a `while` loop
produced a back edge, or that an early return drops what it skips.

The printer is complete on purpose — locals, blocks and projections all appear —
so that a printer change that silently drops information fails the round-trip
test instead of quietly producing less MIR.

Type annotations carry both a name and an interned id, as `str@4`, so the output
is readable to a person and exact for a machine.

## Consequences

- Ownership checking in Phase 4 becomes a dataflow problem over blocks with no
  need to understand expression shape.
- The backend receives a uniform representation: every function and constant is
  a `Body`.
- Temporary-heavy MIR is verbose, and optimisation passes in Phase 5 must remove
  most of it. This is deliberate: correctness first, then a cleanup pass whose
  effect can be measured.
- Order-of-evaluation is fixed by the lowering rather than left implicit.

## Alternatives considered

**Lower sugar in HIR, keep MIR minimal.** Rejected: `?` and `&&` need branches,
so either HIR grows a control-flow representation (making it not a tree) or MIR
receives already-branchy shapes it cannot verify.

**Keep nested expressions in MIR operands.** Rejected: it moves the complexity
of "which moves are inside this statement" into every later pass.

**Compute drops during lowering, at scope exits.** Rejected: a `return` inside a
loop must drop bindings declared in an enclosing block, which is a property of
the graph, not of the statement being lowered.
